Waterfall SDLC Model

1. Requirements Analysis

▼

Gathering and documenting all user, system, and functional requirements. Defining the project scope, objectives, and constraints. Output: Requirements Specification Document.

2. System Design

▼

Defining the system architecture, hardware/software requirements, database design, module interfaces, and data structures based on the analyzed requirements. Output: Design Documents (High-level & Low-level).

3. Implementation (Coding)

▼

Writing the actual code based on the design specifications. Translating the design into a machine-readable form. Unit testing is often performed by developers here. Output: Source Code, Executables.

4. Testing (Verification)

▼

Integrating different modules and testing the entire system for defects and failures. Verifying that the software meets the specified requirements. Includes integration testing, system testing, acceptance testing. Output: Test Reports, Bug Fixes.

5. Deployment (Installation)

▼

Installing the tested software onto the production environment or releasing it to the customer. Making the system available for use. Output: Operational System.

6. Maintenance

▼

Making modifications after deployment to fix issues (corrective), adapt to environmental changes (adaptive), or add new features (perfective). This is often the longest phase. Output: Updated System Versions, Patches.
